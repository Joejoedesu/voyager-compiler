# Integration and evidence

Use for: Coordinate adoption, combine changes, resolve cross-role conflicts or report completion.

## Binding and ownership

`Coordination: no compiler extension binding`. Route work across named interfaces and check evidence. This is not another compilation stage.

## Load for this task

User objective and authorized scope, current checkout, relevant procedure or role, accepted contracts and source/evidence identities.

## Implementation decisions

| Problem | Next action |
| --- | --- |
| Starting with no target implementation | Use registration’s fresh-target route and authoritative specs. Establish one complete compilation-to-endpoint path, then broaden real workload coverage and compare legal alternatives. |
| Several roles touch one execution assumption | Provide one case, contract and artifact boundary; integrate model, builder and emitter changes together. Delegate only when authorized and separable. |
| Asked for comparable implementation quality or performance | Separate coverage, numerical correctness, endpoint behavior, model ranking and measured speed. Use fixed workload/configuration boundaries; report what remains unverified. |

## Do

1. Choose the adoption step and route work to the needed roles. Give each task the minimal relevant contract sections, case and decision history; reuse applicable decisions and evidence in the task handoff.

2. Use parallel workers only for separable tasks when authorized. Reserve a single writer for shared files and coordinate coupled model/builder/emitter changes under one execution assumption.

3. Integrate handoffs by checking changed interfaces, artifacts and validation evidence. Summaries retain uncertainties and provenance; a confident worker claim is not an acceptance result.

4. Preserve the pinned comparators and requested scope. Freeze the source/artifact snapshot submitted to acceptance runs; develop a separate candidate independently if needed. Use existing local assets/environments and label later documentation-only edits separately.

## Do not

- Turn an old report, missing status marker or route step into an implementation task without checking current code and evidence.
- Require a stage badge, exact-control campaign or new performance measurements unrelated to the requested result; relabel host/collateral checks as device proof.

## Handoff and validation

Return supported work and gaps, actual host/emission/endpoint evidence, estimates versus measurements, changed source and reproducible artifacts. State each claim at its validated scope; no stage-completion label is required.

Use the task-local [adoption work record](../adoption/harness.md) across resumptions.
A pending check names its tested artifact; a passing check does not close an
unrelated optimization opportunity or validate a changed candidate.

Run the affected contracts and required gates once changes settle. Preserve pinned numerical warnings as warnings; emitted collateral is not endpoint execution. Do not replace a failed pin without authorization. When a replacement is authorized, preserve the previous snapshot and record the resolved search policy, input identities and retained numerical warnings.
